## 1. Executive verdict / exact definition of truth

1. **Do not start over.** Real Gradle/Kotlin code exists in core/foundation, apps/android, apps/desktop and five engine adapters. Android debug APK and Compose desktop distributions were assembled in GitHub Actions (M4 green on baseline), and historical Linux/JVM engine interop receipts exist. Neither mere research nor an empty app template.
2. **Not a real-device-verified VPN beta yet.** No physical Android device execution, no Android tunnel packet/IPv4/IPv6/DNS/leak/reconnect receipt, no current production signing or Store review is evidenced. An APK build does not prove tunneling. The direct Android service has multiple source-observed lifecycle and compatibility risks.
3. **Engine CI is not all green.** At least two independent gate workflows retain failures: Xray REALITY and runtime contract, and Mihomo TUIC v5. This does not negate separate passing M4 APK/desktop jobs.
4. **Recommendation:** KEEP existing Kotlin Multiplatform (KMP) foundation + native Android Compose/VpnService + desktop Compose; do not migrate to Flutter for the 6-day Android beta. Flutter is a possible future presentation spike, not a validated acceleration or a substitute for VPN/TUN platform engineering.
5. **Minimal Android beta target:** one explicitly selected Xray/VLESS path with reproducible physical-device end-to-end evidence, reliable connect/disconnect, secret hygiene and clear unsupported-feature messaging. External subscriptions, enterprise protocols, PVNetwork purchase and iOS are follow-on verticals, not silently finished in that beta.
6. **Most urgent code issue:** apps/android/.../PvVpnService.kt calls VpnService.Builder.excludeRoute(), an **API 33+** method, while build.gradle.kts advertises minSdk 26 and runtime only rejects API below 29. Devices on API 29–32 can fail at runtime. Official Android API reference: https://developer.android.com/reference/android/net/VpnService.Builder (excludeRoute: Added in API level 33). Fix / gate this before any beta install.

This audit distinguishes **OBSERVED** (source / GitHub metadata), **VERIFIED-CI** (the linked Actions job succeeded for its exact scope), **DOCUMENTED-HISTORICAL** (prior written claim, not repeated here), **UNVERIFIED** (missing live/device evidence), **BLOCKED** (known incompatible/failed gate), and **PROPOSED** (implementation action). Never collapse these into a single "works" flag.

## 4. Concrete Android defects and risks — file-level evidence

### A-01 / P0 — API-level crash path, NOT merely an SDK preference

**Source:** [apps/android/build.gradle.kts lines 10–21](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/build.gradle.kts#L10-L21) sets minSdk 26, target 36. [PvVpnService.kt lines 100–120](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/PvVpnService.kt#L100-L120) only gates below Q (29) then calls excludeRoute(IpPrefix). **Official API introduced at 33**: https://developer.android.com/reference/android/net/VpnService.Builder#excludeRoute(android.net.IpPrefix). **OBSERVED defect with authoritative platform corroboration.** On 29–32 invocation can throw NoSuchMethodError. Branch condition does not make the call safe. **Action:** choose a truthful compatibility target: either support 26–32 with an alternate safe route/protect design tested per SDK, or explicitly raise the effective/min SDK to 33 with product approval; do not keep a false 26–32 promise. Acceptance: no unhandled missing-API error on any device claimed supported.

### A-02 / P0 — CONNECTED can mean "JNI started", not packets flowing

**Source:** [PvVpnService.kt lines 151–179](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/PvVpnService.kt#L151-L179). The service launches ProcessBuilder Xray then starts hev TProxy; if JNI reports started it immediately emits ConnectionState.CONNECTED without proving SOCKS availability, engine readiness, first packet or remote handshake. **OBSERVED logic; no device proof.** **Action:** service/engine/TUN coordinator, bounded readiness probes and distinct WAITING/ERROR outcomes; test fully established data path before certification; connection status must never certify mere process spawn.

### A-03 / P0 — service lifecycle/race and revocation gaps

**Source:** [PvVpnService.kt lines 40–73, 184–211, 270–279](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/PvVpnService.kt#L40-L73); [VpnHub.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/VpnHub.kt). Every start can create a new Thread/connect path with shared engineProcess/tunnelFd and no single-flight arbitration; watcher reports ENGINE_EXITED but does not force stop/close/release; stop calls startService; START_STICKY null-intent path lacks profile; no onRevoke override in service. Service events are process-local StateFlow only, not durable recovery. **Action:** serialize connect/stop; stopForeground+stopSelf deterministic cleanup; onRevoke/process death/network switch handling; atomic tunnel owner; kill/retry bounded backoff. Acceptance: 20 rapid toggles, permission revocation, kill process, service restart, airplane toggle, Wi-Fi/mobile changes: at most one engine/TUN, no stale CONNECTED or stuck system VPN, no orphan config/process.

### A-04 / P0 — secrets survive as plaintext config and Android deletion leaves secret refs

**Source:** [PvVpnService.kt lines 129–159, 196–211](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/PvVpnService.kt#L129-L159); [Storage.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/Storage.kt); [MainActivity.kt lines 59–63](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/MainActivity.kt#L59-L63). AndroidSecretStore uses Keystore encrypted-at-rest blobs (useful) **but** Xray config with decrypted credentials is written to app-private filesDir/engine/config.json and the observed stop path never deletes that config or tunnel.yml. Delete-profile UI calls profile store remove without deleting associated SecretStore entries. **Action:** private ephemeral config with atomic restrictive permissions, delete in finally/recovery paths, redact diagnostics, securely retire refs only when no profile references them; negative tests for deletion/disconnect/crash. Do not claim Keystore protects the plaintext runtime file.

### A-05 / P0 — routing, DNS and core egress still need packet-level proof

**Source:** [PvVpnService.kt lines 108–120 and 241–269](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/PvVpnService.kt#L108-L120). Source pins DNS 1.1.1.1 and 8.8.8.8, routes v4+v6, excludes only one pre-resolved endpoint IP. No use of VpnService.protect() observed; host may resolve to multiple IPs/families, migrate, or reconnect. **Risk (not an observed leak):** routing loops, resolver leakage, IPv6/UDP mismatch and reconnect failure. Test explicit DNS destinations and both address families with server-side packet captures; support configured DNS and protected upstream sockets, do not assume fixed public DNS always works.

### A-06 / P1 — import and supported-platform claims outrun UI

**Source:** [MainActivity.kt lines 68–98](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/MainActivity.kt#L68-L98) calls **VlessShareLinkImporter only**, despite common Xray ShareLinkParser supporting additional families and desktop using it. Android no subscription URL fetch, QR, deep-link handler, PVNaive/NaiveProxy, backend account, Store billing or other engine UI in source tree. [Manifest](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/AndroidManifest.xml) registers MAIN/LAUNCHER only. **Action:** select VLESS-only beta scope clearly, or add share-link parser with exact adapter capability gating and tests; never accept a format the embedded runtime cannot actually use.

### A-07 / P1 — persistence and reactive UI integrity

**Source:** [Storage.kt lines 101–124](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/Storage.kt#L101-L124) swallows JSON corruption to empty list and writes profiles.json directly rather than atomic replace. [MainActivity.kt lines 110–120, 193–300](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/src/main/kotlin/com/pvnetwork/client/MainActivity.kt#L110-L120) uses ClientState.profileList / selectedProfileId plain mutable values, not observable Compose state (potential stale list/selection). **Action:** repository with atomic transactional writes + corruption recovery, StateFlow observable profile list/current selected; test duplicate imports, delete while disconnected, app relaunch, interrupted write, secret orphan prevention.

### A-08 / P1 — Android build/publishing hardening

**Source:** [Android build.gradle.kts lines 23–37, 59–104](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/android/build.gradle.kts#L23-L104): release is not minified, only arm64 ABI, useLegacyPackaging true, embeds libhev-socks5-tunnel.so, fetches exact-checksum Xray ZIP if the libxray.so target is absent. Existing committed libxray.so must be audited independently; presence causes the fetch task to return before verifying source archive / local binary hash. No native 16KB page-size, engine advisory gate, artifact provenance/SBOM, signing or release build/QA shown. **Action:** verify committed ELF SHA + upstream provenance *even if already present*, documented 16KB/arm64 tests, fail-closed exact binary security/license gates, make debug/release reproducible and signed only on private controlled pipeline. UI logo assets exist but owner-final asset authenticity unverified.

## 5. Desktop / Core / Engine delta against universal PVNetwork

**Desktop remains useful, but not a system-wide VPN yet.** [DesktopVpnController.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/desktop/src/main/kotlin/com/pvnetwork/desktop/DesktopVpnController.kt) provides share-link import, local profiles, subscription fetch, latency TCP test, Xray host runtime, status and win32 proxy. [SystemProxyController.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/desktop/src/main/kotlin/com/pvnetwork/desktop/SystemProxyController.kt) changes HKCU WinINET settings; applications ignoring the Windows system proxy are not covered. Its snapshot lives in memory and shutdown hook, so abrupt kill/reboot does not provide guaranteed persistent restoration. This is a **proxy-client vertical slice**, not a validated full-tunnel Windows VpnService equivalent. WinINET proxy enable failure is logged but DesktopVpnController still shows CONNECTED as engine state, not whole-system traffic assurance.

**Desktop subscription data-consistency risk (OBSERVED):** [DesktopVpnController.kt lines 181–193](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/desktop/src/main/kotlin/com/pvnetwork/desktop/DesktopVpnController.kt#L181-L193) removes old subscription profiles and deletes their secrets before adding new ones; failed middle-stage write can lose old working profiles. [SubscriptionSupport.kt lines 20–101, 109–156](https://github.com/DashSaman/PVN-amirrezagol/blob/main/apps/desktop/src/main/kotlin/com/pvnetwork/desktop/SubscriptionSupport.kt#L20-L156) stores full subscription URLs (potential bearer tokens) in local subscriptions.txt, accepts HTTP and HTTPS, and has no persisted rollback/snapshot/size bounds shown. Propose staged validate + atomic replace + preservation of favorites/customizations + secure URLs; do not copy desktop logic to Android unreviewed.

**Core boundary is reusable but incomplete:** [ConnectionState.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/core/foundation/src/commonMain/kotlin/com/pvnetwork/core/connection/ConnectionState.kt) already contains strict transitions, [CoreAdapter.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/core/foundation/src/commonMain/kotlin/com/pvnetwork/core/adapter/CoreAdapter.kt) formalizes capability descriptors and PreparedConnection, [PVProfile.kt](https://github.com/DashSaman/PVN-amirrezagol/blob/main/core/foundation/src/commonMain/kotlin/com/pvnetwork/core/profile/PVProfile.kt) is the canonical profile; Account/Entitlement classes/tests exist. There is **no observed** commonMain platform/PlatformVpnService.kt, connection/ConnectionCoordinator.kt, subscription/*, routing/*, dns/*, support/* implementation. Android PvVpnService currently bypasses the proposed shared coordinator. Implement thin abstractions and tests rather than rewriting these proven foundations.

**Engine scope remains precise:** Xray path on Android is selected; WireGuard and OpenVPN Linux harness success does not supply Android TUN engines; Mihomo/OpenConnect are JVM host adapters only; no source-verified NaiveProxy adapter. A full 93-protocol product or complete Android protocol stack is unimplemented and is **not** required to prove an Android VLESS beta. The exact release protocol matrix and upstream licensing are Chat 03 and Chat 02 ownership, respectively.
