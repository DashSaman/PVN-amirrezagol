## Identity and architecture

TINA is a Barracuda proprietary VPN protocol/extension used by CloudGen Firewall. Barracuda explicitly distinguishes TINA from standard IPsec and requires Barracuda VPN Client / Network Access Client for TINA client-to-site, while standard IKE/IPsec clients are used for standard IPsec services. Therefore generic IPsec compatibility cannot be promoted as TINA compatibility.

The canonical remote-access path is Barracuda VPN Client -> CloudGen Firewall VPN service. Windows can install the VPN component alone or as part of Network Access Client. Barracuda documentation also describes GUI macOS and command-line Linux/OpenBSD/FreeBSD-family client paths. CudaLaunch on Android includes a TINA client; iOS CudaLaunch instead manages the native IPsec client, so iOS must not be falsely marked as a native TINA client based on the mobile brand alone.

## Transport and data-plane boundary

Current CloudGen documentation exposes TINA transports UDP, TCP, UDP+TCP hybrid, ESP and routing for tunnel use. Current tunnel settings document TCP default port 691 and TCP 443 when traversing HTTP proxies; UDP/TCP and ESP have different NAT/performance properties. TINA supports proxy traversal via HTTP/SOCKS in client contexts. Barracuda describes TINA as a proprietary extension of IPsec with modified initial handshake, heartbeat/fast-failover and multiple encapsulation transports.

IPv6 is supported for the VPN envelope in documented deployments, while traffic inside current TINA client/site tunnels remains IPv4 in the cited client-to-site guidance. Do not infer full dual-stack payload support from IPv6 endpoint support.

## Authentication and cryptography

Barracuda client-to-site documentation supports user/password, X.509, X.509 plus user/password, `.lic` personal-license files, SAML and current TOTP MFA surfaces depending on deployment. Client-certificate examples require a valid client certificate plus username/password. CloudGen includes a CA usable for TINA certificates.

Current CloudGen 10.5 transport documentation includes AES/AES256/AES-CTR/AES256-CTR and legacy choices, plus authentication/integrity choices such as SHA256/SHA512/GCM and legacy hashes. Barracuda explicitly labels several legacy algorithms not recommended. PVNetwork must preserve the current strong-crypto policy and never normalize DES/3DES/MD5/SHA1-era options as recommended defaults merely because the product can parse/configure them.

## Routing, profiles and client lifecycle

The VPN client supports multiple named profiles and Windows import of profiles generated by Firewall Admin. Current macOS self-service documentation describes importing `.vpn` group-policy files. Features include selective routing, redundant VPN gateways, optimal-gateway selection, Always On on PCs and fast restoration after connection loss. CloudGen controls client-to-site policy, routes and optional endpoint-health integration.

Windows supports standard and unattended/preconfigured installation. Linux/macOS CLI configuration is available, with Linux typically requiring root/equivalent for operation. The VPN client and Network Access Client are separable components; health-agent/personal-firewall capabilities must not be conflated with the TINA wire protocol.

## UI, storage and diagnostics

V1 client surfaces include VPN profile creation/import, server/transport/proxy selection, authentication/certificate selection, connect/disconnect, profile list, route/gateway behavior, Always On/reconnect where supported and logs/status. Certificates may use platform stores (for example macOS Keychain support appears in Barracuda release documentation); exact proprietary storage internals are not publicly source-auditable and remain bounded N/A.

CloudGen records TINA client-to-site accounting/login/logout in VPN service logs and exposes server-side VPN configuration/diagnostic surfaces. Full menu-by-menu client and Firewall Admin reconstruction belongs to V2.

## Source/version/license boundary

No canonical public source repository for the complete TINA protocol engine, Barracuda VPN Client, Network Access Client or CloudGen VPN service is identified in the authoritative Barracuda documentation reviewed here. TINA is explicitly proprietary. Treat complete first-party code, binaries, assets and protocol implementation as proprietary/reference-only. No source SHA or redistribution right may be invented.

Current documentation is actively maintained in 2026 and covers CloudGen Firewall 9.0/10.5 and current Network Access/VPN Client material. Exact binary version/hash/signature pinning belongs to packaging/runtime certification because the authoritative docs expose product/release families rather than a reusable source commit.
